# 051: 表示名を決められないパス指定は、語幹が空白だけになるファイル名で再現する

## ステータス

承認済み

## コンテキスト

spec の異常系は「`workflow:` キーがなく、ファイル名由来の表示名が不正になるパス(拡張子を除くと空になるファイル名等)」を求める。これは「定義は読み込めたが表示名だけが決まらない」という処理フロー上の位置(load のあとの display_name)を通す唯一のケースである。

しかし Rust の `Path::file_stem` は `.yaml` のような先頭ドットのファイル名を「拡張子なし・語幹 `.yaml`」として返すため、「拡張子を除くと空」の状態はファイル名からは作れない。`WorkflowName::parse` が拒むのは空文字列と前後の空白の2つである。

## 決定

語幹が空白だけになるファイル名(` .yaml`)を置いて再現する。ファイルは実在させ、内容は有効な定義にする。

## 検討した代替案

- ファイル不在や YAML 不正のフィクスチャで代用する — load の段階で落ちるため、表示名の決定を通らず、行の趣旨が検証されない
- `WorkflowName::parse` の制約を緩めて「拡張子を除くと空」を作れるようにする — 表示名の制約はドメインの判断であり、テストのために緩める理由がない

## 影響

- spec が例示する状況のうち、実際に到達できる形でケースが書ける
- 到達するエラーは「空」ではなく「前後の空白」になる。spec 側の例示に「語幹が空白のみ」を含める言い換えを提起する
