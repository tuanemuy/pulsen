# 005: add はベースブランチも登録時に検証する

## ステータス

承認済み

## コンテキスト

ADR-003 で `add` はリポジトリパスを登録時に検証すると決めたが、ベースブランチの存在は対象外だった。ブランチ名の typo は利用者が最も踏みやすい入力エラーであり、検証しないと「登録は通るが worktree 作成失敗 → リトライ上限超過で stopped」という遅延表面化になる。

## 前提

- ワークフロー解決・YAMLパース・エージェント名解決・リポジトリパスはすべて登録時に検証される(ADR-003)
- 登録後にブランチが削除されるケースは登録時検証では防げない

## 決定

`add` は登録時にベースブランチの存在も検証し、不正ならエラーとしてタスクを作らない。ADR-003 の「境界で一度だけ検証する」原則の範囲拡張であり、登録後の消失は従来どおり worktree 作成失敗の実行時経路(ADR-001)が受ける。

## 検討した代替案

- 検証せず遅延表面化を文書化するのみ — typo の発覚が数tick後の凍結通知になり、他の入力の検証時点と非対称なため不採用(ADR-003 と同じ理由)

## 影響

- 入力起因のエラーはすべて `add` の時点で返り、実行後に表面化するのは環境変化(リポジトリ・ブランチの消失等)だけになる
