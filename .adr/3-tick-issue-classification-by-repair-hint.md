# ADR: 前提の破れは修復の手がかりごとに tick の報告分類へ分け、遷移関数を呼ばずにドメインのエラー型を作らない

## ステータス

承認済み

## コンテキスト

tick が「書き込まずに報告してスキップする」経路は、既存の分類や既存のエラー型に相乗りさせたくなる。実際に2箇所でそうなっていた。

1つめ。手続きDの冒頭は、`current_attempt` が None(不変条件2の破れ)に加えて `current_attempt.process` が None(不変条件3の破れ)を検査して報告する(TC-exec-tick-022)。既存の `TickIssue::MissingCurrentAttempt` は attempt 参照そのものが無い場合だけを指すもので、不変条件3 の破れをこれに相乗りさせるか、新しい分類を足すかを決める必要があった。ADR-096 は「遷移エラーの `MissingCurrentAttempt` と tick の報告分類の `MissingCurrentAttempt` は同じ事実の別文脈での報告」として重複を許したが、それは**同じ事実**だからである。

2つめ。手続きDの判定アームは、判定コマンドを持つステータスで `task.workspace()` が None のとき、判定コマンドの起動も書き込みも行わずに報告する。実装はこのとき `TransitionError::WorkspaceNotSet` を組み立てて `report_transition` に渡していた。ところがこの経路は遷移関数を一度も呼んでいない。`WorkspaceNotSet` は spec 上「workspace 未確定での `record_launching`」を指す前提の破れであり(`spec/domains/task.md#エラー型`)、遷移関数だけが返す値である。ユースケースが自作すると、表示は「遷移の前提が成立しません(ワークスペースが未確定)」になり、遷移を試みてすらいないという事実と食い違う。

## 前提

- tick は前提の破れに対して書き込まず、修復は人間が行う。したがって報告の解像度がそのまま復旧の速さになる
- `TickIssue` の振り分けは `cli::render` の網羅 `match` が受けるため、変種の追加は表示側でコンパイルエラーになる

## 決定

**破れの事実が違い、人間に求める修復も違うなら、分類を分ける。**

- 不変条件3 の破れには新しい分類を足す。不変条件2 は attempt 参照そのものが失われている(run ディレクトリへの導線が無い)、不変条件3 は attempt はあるが同定情報が無い(pid ファイルから復元できる可能性がある)。同じ文言に畳むと、`cli::render` が出す案内が修復の入口を示せなくなる
- 不変条件4 の破れには `TickIssue::MissingWorkspace { task_id }` を足し、`TransitionError::WorkspaceNotSet` の自作をやめる。ここで起きたのは「判定コマンドへ渡す `WORKSPACE` を組めなかった」であり、修復は帳簿の `workspace` を埋めることになる

**ドメインのエラー型は、それを返す遷移関数を呼ばずに作らない。** `TransitionError` 側は触らない — `WorkspaceNotSet` は `record_launching` の前提として引き続き値で返り、遷移関数を全域に保つ判断(ADR-096)はそのまま生きる。

## 検討した代替案

- **既存の `MissingCurrentAttempt` に不変条件3 の破れを相乗りさせる** — ADR-096 が重複を許したのは同じ事実だったからで、ここは事実も修復も違う
- **`TransitionError::WorkspaceNotSet` をユースケースが組み立てて報告する(従来の形)** — 遷移を試みていないのに「遷移の前提が成立しません」と表示され、値の出所と意味が食い違う
- **`TransitionError` 側に「遷移を試みていない」変種を足す** — ドメインのエラー型が、遷移関数を呼ばない経路のために増える。報告の分類はユースケースの関心なので `TickIssue` 側に置く

## 影響

- 表示から修復の手がかりが読み取れる。tick は書き込まずに人間へ委ねるので、報告の解像度がそのまま復旧の速さになる
- ドメインのエラー型を、それを返す遷移関数を呼ばずに作る経路が消える。値の出所と意味が構成上一致する
- 書き込みが無い経路なので、`cli::render` の振り分けでは「スキップ」の見出しに入る(ADR-098)
- トレードオフ: `TickIssue` の変種が2つ増える。分類の列挙は網羅 `match` で表示側が受けるため、足し忘れはコンパイルエラーになる
