# ADR: アトミックな置換・移動・読み取りは、OS が返した拒否コードで分類したうえで上限つきに再試行する

## ステータス

承認済み

## コンテキスト

Windows の `MoveFileEx`(`NamedTempFile::persist` と `fs::rename` の実体)は、対象を他のハンドル(ロックを取らない読み手・ウイルス対策のスキャン)が開いている間、置換と移動を `ERROR_ACCESS_DENIED`(5) / `ERROR_SHARING_VIOLATION`(32) で拒む。さらに置き換えられる側は delete-pending に落ちるため、その窓で `CreateFile` を掛けた読み手も同じコードを受ける。unix の `rename` と `open` は開いているハンドルに影響されないので、この経路は Windows にしか現れない。3 OS の CI を回して初めて実測された(`util::atomic` のユニットテストが `Os { code: 5, kind: PermissionDenied }` で落ちた)。

「読み手はロックなしで常に一貫した内容を見る」は永続化ポートの契約(spec/domains/task.md `TaskRepository`)であり、置換の窓は書き手と読み手の両方に当たる。片方だけを吸収しても契約は満たせない。

窓を踏む経路は3つある — `write_atomic`(`persist`)、`rename_atomic`(`archive` の経路、TC-port-task-repository-044)、`FsTaskRepository` の内容の読み取り(`lookup` / `list` / `save_degraded`)。CI が実測したのは最初の1つだけだが、テストは最初の失敗で停止しており、残る2つは「赤でない」のではなく**まだ観測されていない**だけである。原因が同一だと分かっている経路を観測の順番だけを理由に残すと、CI を往復させて同じ修正をもう一度書くことになる。3つとも同じ機構で扱う。

分類を OS ごとに変える以上 `cfg` が要る。`.adr/1-platform-separator-set-without-cfg.md` は「条件付きコンパイルではなく std の定数から選ぶ」を採っているが、それが成立するのは分岐する値が std に定数として出ている場合(`MAIN_SEPARATOR`)に限られ、Win32 のエラーコードは std に無い。`util/atomic.rs` は既に `sync_dir` を `#[cfg(unix)]` / `#[cfg(not(unix))]` で分けている共通ユーティリティであり、CLAUDE.md が「アダプター層に隔離する」と言う対象の中にある。

`.adr/10-os-differences-absorbed-by-probe-and-allowed-skips.md` の境界では、置換・移動の手順を保ったまま失敗時の再試行やエラー分類をその手順の中に足すことは、CI の赤をその場で吸収する側にある。置換方式・シグネチャ・契約は変えない。

## 検討した代替案

再試行するエラーの分類:

- すべての失敗を再試行する — 権限そのものの不足・容量の不足のように時間で解けない失敗まで、上限を使い切るぶんだけ遅らせる。呼び出し側が受け取るエラーは同じでも、返るのが遅くなる
- `io::ErrorKind::PermissionDenied` で分類する — unix の `rename` が返す `EACCES` も同じ `kind` に落ちるため、時間で解けない失敗を同様に遅らせる。unix の挙動を変えないという条件に反する
- 採用: **OS が返した生のコードで分類する**。ただし 5 / 32 は unix では別の errno(`EIO` / `EPIPE`)なので、OS を問わず同じ数値で分類することはできない

再試行の置き場所:

- 読み取りの再試行を `adapter/task_repository.rs` に書く / 移動の再試行を `rename_atomic` の中に直接書く — 分類・上限・バックオフが操作ごとに二重化する。CLAUDE.md「アトミック性・排他が要る操作は共通のユーティリティに集約し、個別に再実装しない」に反する
- 置換用の `persist_with_retry` を `fs::rename` と `fs::read` も扱えるよう拡張する — 名前が実態と合わなくなり、呼び出し側が「置換なのか移動なのか」をフラグで渡すことになる
- 採用: **再試行のループだけを切り出し、操作ごとに薄い当て先を残す**。障害は `NamedTempFile::persist` が一時ファイルを消費し、失敗したときだけ返してくることで、`FnMut() -> io::Result<T>` の形の共通ループには載らない。載せるには一時ファイルを `Option` に入れて呼び出しごとに取り出す形になり、不変条件違反でないところに `unwrap` が生まれる — これは下の「状態を型引数にする」で解いた

## 決定

置換・移動・読み取りを、分類・上限・バックオフを共有する1つの再試行機構に載せる。

- **分類は `transiently_denied` の1つに閉じる。** `#[cfg(windows)]` 版が `ERROR_ACCESS_DENIED` / `ERROR_SHARING_VIOLATION` だけを真とし、`#[cfg(not(windows))]` 版は常に偽を返す。**unix では再試行の経路に一度も入らない。** Windows で置換・移動・読み取りを拒む条件は同じ(他のハンドルが対象を開いている・対象が delete-pending にある)なので、コードの組を操作ごとに分ける根拠がない
- **上限は `MAX_ATTEMPTS` = 10 回、待ちは 1ms から試行ごとに倍**(累計で最大 511ms)。名前に置換を指す語を入れないのは、同じ上限が移動と読み取りにも掛かるため。上限は `NonZeroU32` で持つ — 「1回は試みる」を含むので 0 を型で表現不能にし、数え上げ側から引き算を消す
- **待ちの列を `retry_waits()` という純粋関数に切り出し、再試行ループはこの列だけを消費して眠る。** 公称の 511ms はこの列の和であり、doc と本 ADR がこの数値を根拠にするときの唯一の出典である。ユニットテスト `再試行に費やす待ちの合計は公称する上限と一致する` が一致を固定する
- **再試行のループは `retry_while_transient` に1つだけ置く。** 試行は失敗時に「次の試行へ持ち越す状態」をエラーと一緒に返す(`Result<T, (io::Error, S)>`)。`persist` は `S = NamedTempFile`、`fs::rename` と `fs::read` は `S = ()` になる。状態を型引数にすることで、消費する操作としない操作を同じループに載せつつ `Option` と `unwrap` を持ち込まない
- **`persist_with_retry` / `rename_with_retry` / `read_with_retry` は分類を引数に取る薄い当て先として残す。** 打ち切りの振る舞い(上限で止まる・元のエラーを返す)を、エラーがどう分類されるかと独立に、どのプラットフォームでも検証できるようにするため。この seam が無いと、再試行の上限を検証できるのは Windows だけになる
- **打ち切りを表す独自のエラーに差し替えず、OS が返した拒否をそのまま返す。** エラーの意味は変えない。`NotFound` は一時的な拒否ではないので初回で返り、「消えたエントリ」と「読めないエントリ」の判別は不変
- **読み取りも `util/atomic.rs` に置く(`read_atomic`)。** 窓を作る側と吸収する側が同じファイルに揃い、出典が1つで済む。`FsTaskRepository` の内容の読み取りは `fs::read` ではなくこれを通す
- **対象外を明示する。** `symlink_metadata`(std の Windows 実装は共有違反で `FindFirstFileW` にフォールバックする)、`read_dir`、`config_store` / `workflow_store`(`write_atomic` で書く経路が無く、置換の窓が生じない)
- **契約の主張をユニットテストと適合スイートで揃える。** `読み手は旧内容か新内容のどちらかだけを観測する` は「読めたときだけ内容を見る」形で読み取りの失敗を許容しており、ポート水準の契約より弱いことを主張していた。適合スイート側に合わせ、`read_atomic` が成功することを要求する

分類が空である unix では、公開関数が再試行に入る様子を原理的に観測できない。そのためテストを3つに分ける。

1. `transiently_denied` の真偽そのもの — 期待値を `cfg!(windows)` から導くので全 OS で走り、分類の中身が動けばどの OS でも落ちる
2. 3つの当て先が上限内で解ける拒否を吸収すること — 阻害要因は別スレッドが取り除き、公開経路そのものを呼ぶ
3. 公開関数が返した拒否が予算の対象にならないこと — 公開関数が実際に返したエラーを同じ分類に掛け、費やす予算が 0 であることを見る

3 を経過時間との比較にしないのは、壁時計で測ると判定の基準がランナーの速さに依存し、遅い Windows ランナーで `NotFound` の往復が 511ms を超えれば実装と無関係な赤になるため。**代わりに落ちるのは、公開関数が `transiently_denied` を渡している配線そのものである** — 緩い分類に差し替えても `NotFound` であることは変わらないので、3 は配線の変異を殺さない。配線が壊れたときの被害は有界な遅延(1回あたり最大 511ms)に限られ、正しさは変わらない。2 の阻害要因を分類器の副作用で取り除く形は採らない。最終試行では分類器が呼ばれないため、そこでは状況が変わらず、テストが検証するものが「再試行の吸収」から「分類器がいつ呼ばれるか」へすり替わる。

## 影響

- 置換・移動・読み取りのシグネチャと契約(失敗時に一時ファイルを残さない・対象が変わらない・読み手はロックなしで常に一貫した内容を見る)が変わらない。読み手を待たせる方向(ロックの導入)に倒さずに済む
- 契約が書き手と読み手の両側で揃う。ユニットテストが主張する内容が適合スイートと同じ強さになり、片方だけが緩い状態が消える
- unix では分類が常に偽なので、挙動が実装前と一致する
- 分類・上限・バックオフの出典が1箇所に保たれ、片方だけ値が動く事故が起きない。上限が壁時計ではなく待ちの列の和として検証されるので、バックオフの伸び幅・初回の待ち・回数のどれを変えても、ランナーの速さに関わらずユニットテストが落ちる(`*2` を `*4` にすると実際の予算は約87秒になる)
- トレードオフ: Windows で**時間で解けない** `ERROR_ACCESS_DENIED` を踏んだ場合、失敗が最大 511ms 遅れる。Win32 のコードからは「他のハンドルが開いている」と「権限が無い」を区別できないため、この取り違えは分類の精度では消せない。上限を持つことで、遅延が有界であることだけを保証する
- トレードオフ: **511ms は1回の呼び出しあたりの上限で、呼び出し側で合成される。** `save_degraded` は読んでから書くので最大2倍、`list` はエントリ数 N だけ読むので最大 N 倍になる。有界であることは変わらないが、境界はポートの操作ごとに数え直す必要がある。tick は排他ロックを保持したまま読むので、この遅延がロックの保持時間にそのまま乗る
- トレードオフ: **短い待ちは OS のタイマー粒度に丸め上げられる。** Windows の既定は約 15.6ms 刻みなので、1ms・2ms・4ms と刻んだ前半の待ちは実際にはそれより長くなる。再試行が実際に発火する唯一のプラットフォームでの実測が公称の 511ms を上回る、という向きにだけズレる
- トレードオフ: 共通ループが型引数を2つ持つ。`S` は `persist` の都合(一時ファイルを消費し、失敗したときだけ返す)、`T` は読み取りの都合(値を返す)から来ており、どちらにも実際の呼び出し元がある。呼び出し側が見るのは3つの薄い関数だけなので、この都合は `util/atomic.rs` の中に閉じる
- トレードオフ: 一時ファイルを抱えたままの時間が、`persist` の前後の数マイクロ秒から再試行の間ずっと(最大 511ms)に伸びる。契約「失敗した場合は一時ファイルを残さない」は関数が返る限り守られるが、その途中でプロセスが落ちた場合は契約の対象外で、掃除する主体もいない。`list` は `TaskFilePath::parse_file_name` で命名形式に合わないエントリを弾くので、残った `.tmpXXXX` が走査に混ざることはない
- トレードオフ: 移動と読み取りには実測より先に手を入れている。置換で同一原因が実測済みであることと、置換と移動が Windows で同じ条件に拒まれることを根拠とする
- トレードオフ: **並行テストの読み手が無制限にスピンする一方で書き手だけが予算を持つ非対称は、テストの中にしか存在しない。** 製品側の読み手(`FsTaskRepository` の `lookup` / `list`)はスピンせず、`read_atomic` を1回通るだけである。読み手ループには `thread::yield_now()` だけを入れて病的な CPU 飢餓を取り除き、読み取り回数の上限やスリープでレースを潰す形は取らない — それは検出したいインターリーブの窓そのものを消す
