# 061: 呼び出しの無い `pub` はレイアウトの構築時検証に対応するものだけ残す

## ステータス

承認済み

## コンテキスト

`PulsenHome::worktree_root()` は、worktree を作る操作が無い本スライスのどこからも呼ばれない。同じ「呼び出しが0の `pub`」として `Runtime::home()` を削除した判断があり、扱いが割れて見える。`pub` は dead_code 検査に掛からないので、基準が無ければ「後で使う」を理由にいくつでも残る。

## 決定

呼び出しの無い `pub` を残すのは、ADR-031 がホームのレイアウトとして列挙し、**構築時に値として検証している**項目に限る。残す場合は why をコードに添える。

- `worktree_root`: `WorktreeRoot::parse` による絶対性の検証が `PulsenHome::new` の一部であり、ホームが使えるかどうかの判定に効いている。導出結果を取り出す口が無ければ、検証だけが残って使い道が消える → 残す
- `Runtime::home()`: 結線の途中結果で、構築時に検証する値でもない → 落とす（必要になったスライスで理由つきで戻す）

基準は `crates/pulsen/src/application/home.rs` のモジュール doc に置き、後続スライスの担当が同じ判断に到達できるようにする。

## 検討した代替案

- 使うスライスまで削る — レイアウトの検証（絶対性）だけが残り、`PulsenHome::new` が何を保証しているかがコードから読めなくなる
- `#[allow(dead_code)]` を付けて内部に隠す — `pub` では警告が出ないため意味がなく、基準も残らない

## 影響

- 「残す / 落とす」が値の検証の有無で機械的に決まり、スライスをまたいで同じ判断になる
- トレードオフ: 条件を満たす項目は使われないまま残る。worktree を作るスライスが入るまで、その正しさは配置を固定するユニットテストでしか裏付けられない
