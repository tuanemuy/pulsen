# 002: pending タスクへの abort を正式仕様とする

## ステータス

承認済み

## コンテキスト

requirements の初版では abort は「実行中タスクの中断」と定義され、登録済みで未実行(pending)のタスクを取り消す手段がなかった。誤登録や不要になったタスクは次のtickで実行されてしまう。

## 前提

- タスクステータスの手動遷移(set-status)は launching / running に拒否され、実行の停止は abort に集約されている
- stopped への「人間によるabort」経路が既に存在する

## 決定

pending のタスクへの abort を許可する。kill 対象が存在しないため、プロセス操作なしで stopped を記録するのみとする。stopped 経路としては既存の「人間によるabort」の内側であり、経路の閉集合は変わらない。

## 検討した代替案

- 専用の cancel / remove コマンドを追加する — 「取り消し = stopped 化」で表現でき、コマンド追加は状態モデルを増やさない abort 拡張より複雑なため不採用
- シナリオ上の提案として注記に留める — intervention のフローが既にこの挙動を前提としており、出典のない仕様が生まれるため不採用

## 影響

- abort の意味が「実行中の中断」から「タスクの停止(実行中なら kill を伴う)」へ広がる
- 取り消したタスクの worktree・タスクファイルは stopped の通常規則に従い保持される(削除はクリーンアップ経由)
