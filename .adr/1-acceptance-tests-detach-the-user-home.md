# ADR: 受け入れテストの起動は既定でユーザーのホームも一時ディレクトリへ向ける

## ステータス

承認済み

## コンテキスト

`.adr/1-acceptance-test-harness-in-tests-common.md` は実バイナリの起動を `tests/common` のビルダーに閉じ、`PULSEN_HOME` の除去を既定の振る舞いにした。しかしホームの解決は3段(`--home` > `PULSEN_HOME` > `~/.pulsen/`)で、既定の段は `HOME` / `USERPROFILE` を読む。ビルダーはこの2つを、テストが明示的に指定したときにしか差し替えていなかった。

そのため、ホームを指定せずに起動を書いたテストは開発者の実 `~/.pulsen/` を解決先にする。config.yaml があればそこにタスクを1件作り、無ければ「未初期化」を返す。どちらも一時ディレクトリの外に出る。既定の段を踏むテストは今後も増える。

## 決定

起動のたびに一時ディレクトリを作り、`HOME` / `USERPROFILE` を既定でそこへ向ける(`PULSEN_HOME` の除去と同じ扱い)。ユーザーのホームを明示する口はその上書きとして残す — 既定の段を観測するテストは、解決先を覗くためにパスを必要とする。

3段のどこを踏んでも一時ディレクトリの外に出ないため、ホームの指定を書き忘れても実ホームには届かない。手動テストの手順も同じ形(`HOME=$(mktemp -d)` を前置き)に揃える。

## 影響

- 「実ホームに触れない」がテストごとの規約ではなくビルダーの不変条件になる。既定の段の経路を後続スライスが増やしても安全側に倒れる
- トレードオフ: 起動1回につき一時ディレクトリを1つ作る。その生存期間を子プロセスの終了まで保つ必要がある
