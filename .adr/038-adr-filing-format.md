# 038: `.adr/` の起票は正本の既存フォーマットに合わせる

## ステータス

承認済み

## コンテキスト

`.adr/` は `## ステータス` / `承認済み` という日本語の見出しと語で運用されている。一方、スライスの作業ログ(`.thread/<Issue番号>/adr.md`)は `### Status` / `Proposed` / `Accepted` で書かれ、記録基準を満たしたエントリだけが `.adr/` へ昇格する(ADR-035)。昇格のたびに書式がそのまま持ち込まれると、正本に2つの書式が混在し、「どの決定が実装で裏を取られたか」の機械的な確認が書式ごとに分かれる。

## 決定

`.adr/` に置くエントリは、既存の書式で書く。

- 見出しは `## ステータス` / `## コンテキスト` / `## 決定` / `## 検討した代替案`(あれば) / `## 影響`
- ステータスの語は **提案中** / **承認済み** / **superseded by NNN**。作業ログの `Proposed` / `Accepted` はそれぞれ 提案中 / 承認済み に対応する

作業ログ側の書式は変えない。書式の変換は昇格の作業に含める。あわせて、作業ログのエントリが昇格済みかどうかは Status 行に `.adr/` のファイル名があるかで判別できる状態に保つ。

## 影響

- `.adr/` 全体で見出しとステータスの語が1つに揃い、`grep -l 承認済み .adr/*.md` のような機械的な確認が全件に効く
- 作業ログを索引として使えば、昇格済みと未昇格を突き合わせられる
- トレードオフ: 作業ログと正本で語が異なるため、昇格時に書式の変換が1手間入る
