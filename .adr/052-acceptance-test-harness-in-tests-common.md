# 052: 受け入れテストの実バイナリ起動と別プロセスのフィクスチャは `tests/common` に集約する

## ステータス

承認済み

## コンテキスト

受け入れテストはすべて実バイナリを起動する。各テストが `Command` を直接組み立てると、環境変数 `PULSEN_HOME` の除去(実行環境の設定に結果を左右されないため)やカレントディレクトリの指定を書き漏らしたテストだけが環境依存でフレーキーになる。漏れは緑のまま潜伏し、他人の開発環境で初めて表面化する。

また、ロックを保持する別プロセスのフィクスチャ(ADR-032)は、適合テストと異常系の受け入れテストの両方が必要とする。

## 決定

- 実バイナリの起動を `tests/common` のビルダー1つに閉じ、**環境変数の除去を既定の振る舞いにする**。各テストは「ホーム・ワークフロー・リポジトリ・フラグ・カレントディレクトリ」を意図として指定するだけにする
- 別プロセスのフィクスチャ(ロック保持プロセスの起動・強制終了・解放)は `tests/common` に置き、適合テストのハーネスもここを使う

後続スライスがサブコマンドを足すときも、起動の口はこのビルダーを拡張する形にする。

## 影響

- 環境依存の取り扱いが1箇所に集まり、テストの本文が spec の言葉だけになる。フィクスチャの起動手順が二重に存在しない
- トレードオフ: 適合テストのファイルが `tests/common` に依存する(フィクスチャの共有であって、適合スイート自体は独立クレートに閉じたまま)
