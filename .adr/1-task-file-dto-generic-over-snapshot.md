# ADR: タスクファイルの DTO はスナップショット表現で型引数化する

## ステータス

承認済み

## コンテキスト

`.adr/1-task-file-json-and-corrupt-classification.md` は2つのことを同時に求める。

- `save_degraded` は解釈できなかったスナップショットの生バイト列をそのまま書き戻す(修復材料を失わない)
- タスクファイルは整形して書き、人間が直接読める状態にする(requirements §9)

`snapshot` を常に生値(`Box<RawValue>`)として持つと、正常なタスクの保存でもスナップショットが1行に潰れて可読性が落ちる。逆に常に構造化した DTO にすると、解釈できないスナップショットを書き戻せない。

## 決定

タスクファイルの DTO をスナップショットの表現で型引数化する(`TaskFileDto<Snapshot>`)。

- `Task` の符号化は構造化した DTO を型引数に取る(整形される)
- `DegradedTask` の符号化と、**すべての復号**は生値を型引数に取る(バイト単位で温存される)

タスク側フィールドの定義と未知キーの拒否(`deny_unknown_fields`)は型引数によらず1箇所のままになる。

## 検討した代替案

- タスク側フィールドを持つ構造体を2つ書く — 同じフィールド群とその検証が二重化し、片方だけ直す事故を生む
- 常に生値で持ち、正常タスクの保存時に整形済みテキストを埋め込む — 埋め込み位置のインデントが合わず、人間可読という意図が中途半端になる

## 影響

- 正常なタスクのファイルは全体が整形され、解釈できないスナップショットはバイト単位で温存される。復号経路は1本のまま
- トレードオフ: DTO に型引数が1つ増える
