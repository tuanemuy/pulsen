# ADR: 置き換わった `.adr/` エントリは決定節を決定時点のまま保ち、置き換えはステータスと影響節が述べる

## ステータス

承認済み

## コンテキスト

`.adr/` のエントリは「その時点で何を材料に何を決めたか」の記録である。後の変更で決定が置き換わったとき、決定節を新しい規則へ書き換えると、当時の前提・退けた代替案・負ったトレードオフが失われ、同じ文書が「当時の記録」と「現行の規則」の両方を名乗ることになる。前提を述べるコンテキスト節と決定節が反転して読めるのもこのときである。

ADR ガイドは「新しい ADR を作り、旧 ADR のステータスを置き換え済みにする。本文は書き換えない」までを定めるが、2つの場合を決めていない。**置き換え後の現行規則がどこに宿るか**(後継 ADR か spec の契約か)と、**決定本体は生きたまま細部だけが古くなったエントリの扱い**である。Issue #9 の spec 追従では5つのエントリがこの状況に当たり、どちらの扱いになるかを揃える必要が出た。

## 前提

- `.adr/` は architecture-audit / spec-sync などの読み手が参照する唯一の永続台帳であり、一覧とタイトルで引かれる
- 「今どうなっているか」の正本は spec / CLAUDE.md が持ち、`.adr/` は「なぜそうなったか」を持つ
- ファイル名は supersede の参照に使われるため、後から変えられない

## 決定

**決定が置き換わったエントリは、決定節と代替案節を決定時点の文面のまま保つ。** 代替案節の各行は当時検討して退けた記録なので、後から採ったものも含めて消さない。

- ステータスに置き換え済みである旨(置き換えた Issue 番号と、後継 ADR があればそのファイル名)と、置き換え後の形を書く
- 影響節に「どの代替案を採ったか」「退けた理由がなぜ成立しなくなったか」「当時のトレードオフがどうなったか」と、置き換え後に生きている規則の所在を書く
- タイトルに `(置き換え済み)` を添える。一覧とタイトルで引かれるため、開く前に性格が分かる必要がある。ファイル名は既存の参照を壊すので変えない

**決定本体が生きていて細部だけが古くなったエントリは、ステータスを `承認済み` のままにして該当箇所を現行へ改訂する。** 置き換え(決定そのものが別の判断に取って代わられた)と改訂(決定は生きたまま形が細かくなった)をステータスで分け、決定節を書き換えてよいのは後者だけにする。

**置き換え後の現行の規則は spec の契約に一本化し、ADR には現行形を持たせない。** 後継 ADR が持つのは判断の経緯・代替案・トレードオフに限る。

## 検討した代替案

- **決定節を現行の規則へ書き換える** — 当時の判断材料が失われ、ADR を残す理由自体が消える。同じ文書が「当時の記録」と「現行の規則」を同時に名乗り、コンテキスト節と決定節が反転して読める
- **置き換わったエントリを削除する** — 参照している他のエントリがリンク切れになり、「なぜ一度その形を採ったか」を辿れない。前提が消えたことに気づかないまま同じ回避策を再発明する余地が残る
- **置き換えと改訂をステータスで分けず、どちらも本文を現行へ揃える** — 決定が別の判断に取って代わられたのか形が細かくなっただけなのかを読み手が区別できない。改訂を重ねるほど履歴が薄れる
- **現行の規則を後継 ADR に書き、spec には書かない** — 同じ規則が ADR と spec の2箇所で別々に育つ。読み手が「今どうなっているか」を ADR から読むようになり、次の変更でどちらかを更新し損ねる

## 影響

- 当時の判断材料と、それが何に置き換わったかの両方が1つの文書から読める
- 置き換えと改訂の違いがステータスから読める。Issue #9 では `.adr/1-workflow-error-file-path-goes-into-free-form-messages.md` が置き換え、`.adr/1-schema-error-location-is-logical.md` / `.adr/1-task-file-json-and-corrupt-classification.md` / `.adr/2-transition-error-holds-classification-only.md` / `.adr/3-notification-procedure-layering.md` が改訂になった
- 意図的な規約からの逸脱: ADR ガイドは旧エントリについて「ステータス行以外は触らない」と定めるが、影響節への追記は認める。置き換えの経緯を書ける節は影響節しかなく、ステータスの1行では「退けた理由がなぜ成立しなくなったか」を残せない
- トレードオフ: 現行の規則は決定節から直接は読めず、ステータスと影響節を経由して spec の契約へ辿ることになる。`.adr/` を規則集として読むことはできない
