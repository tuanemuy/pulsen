# 利用シナリオ一覧

利用者は「AIエージェントに任せる作業をワークフロー化し、複数のタスクを自動で進めたい開発者」。ツールの設定・ワークフロー定義・タスク投入・介入のすべてを同一人物が行う想定。

要件は [../requirements.md](../requirements.md) を参照。

## シナリオ

### セットアップとワークフロー定義

- グローバル設定を作成する(エージェント定義・通知コマンド・各種デフォルト)
- ワークフローYAMLを作成し `workflows/` に配置する
- 外部スケジューラー(cron等)に `tick` の定期実行を登録する
- 作成したワークフローを開発中にファイルパス指定で試す
- 判定コマンドを定義してexit code以外の基準で判定する

### タスクの登録と自動進行

- ワークフロー名と対象(リポジトリ・ベースブランチ)を指定してタスクを登録する
- 登録済みタスクがtickによりステータスを自動で進んでいく(worktree作成 → 各ステータスのエージェント実行 → 判定 → 次ステータスへ)
- 同一対象に複数のタスクを並行して走らせる
- 失敗したエージェント実行が自動リトライで回復する

### 状態の確認と追跡

- タスクの一覧を見る(ステータスでの絞り込み)
- タスクの詳細を見る(現在ステータス・実行状態・worktreeパス・ブランチ・実行メタデータ)
- エージェント実行の出力ログを確認する
- 凍結(stopped)したタスクの原因を調べる
- タスクファイルを直接閲覧・修復する

### 人間の介入と復旧

- stopped確定の通知を受け取る
- 実行中のタスクを中断する(abort)
- 凍結したタスクを再試行する(retry)
- タスクステータスを手動で遷移させる(set-status)
- レビュー待ち等の「何もしない」ステータスから手動で次へ進める

### 終端処理とアーカイブ

- クリーンアップステータスへの到達でworktreeが削除され、タスクがアーカイブされる
- 成果物のブランチを回収する(マージ・PR作成等はツール外の作業)
- アーカイブ済みタスクを一覧・参照する(`ls --all`)

runディレクトリの肥大化対応(明示的なgc操作・保持期間のグローバル設定)は、要件(§9.2)が「別途提供する」とする将来機能であり、本シナリオ体系ではスコープ外とする。
