# ポート適合テスト: ExclusiveLock

対象契約: [../../domains/execution.md#exclusivelock](../../domains/execution.md#exclusivelock)

すべてのプラットフォーム実装が共通で通す。フィクスチャとして、ロックを取得・保持する別プロセスと、ロックを保持したまま強制終了できるテスト用プロセスを用いる。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 誰もロックを保持していない | `try_acquire()` | `Ok(Some(LockGuard))` | |
| 別プロセスが同一グローバルホームのロックを保持中 | `try_acquire()` | `Ok(None)`(プロセス間の排他が成立する。エラーではない) | |
| 別プロセスがロックを保持し続けている | `try_acquire()` | 即座に `Ok(None)` が返る(解放を待ってブロックしない) | |
| `LockGuard` を取得後にドロップ済み | 別プロセスから `try_acquire()` | `Ok(Some(LockGuard))`(ドロップで解放され、別プロセスが取得できる。同一プロセス内の再取得では検証しない — 対象外参照) | |
| ロックを保持したままのテスト用プロセスを強制終了(解放処理を実行させない) | 別プロセスから `try_acquire()` | `Ok(Some(LockGuard))`(保持プロセスの異常終了でも解放される) | |
| 異なるグローバルホームのロックを別ハンドルが保持中 | `try_acquire()` | `Ok(Some(LockGuard))`(ロックはグローバルホームごとに1つで、他のホームの保持に影響されない) | |
| ロック機構自体が利用不能な状況(ロックの置き場を用意できない等。当該状況を再現できるアダプター環境・プラットフォームに限る) | `try_acquire()` | `Err(LockError::Failed { message })`(「取得できなかった」の `Ok(None)` と区別される) | |

## 対象外

- 同一プロセス内の再取得: 契約は排他の単位をプロセス間と定め、同一プロセス内での再取得の挙動を規定しない(tick と状態変更CLIは常に別プロセス。fcntl 系のプロセス単位ロック実装も適合する)
