# テストケース: SetTaskStatus(set-status)

参照元: [ユースケース: Task — SetTaskStatus](../../usecases/task.md)

関連仕様: [requirements §10](../../requirements.md)、[pages set-status・縮退表](../../pages/index.md)、[domains/task](../../domains/task.md)、[scenario/intervention](../../scenario/intervention.md)

## 正常系

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| stopped のタスクと、スナップショットに定義済みの遷移先ステータスがある | 遷移先を指定して set-status する | タスクステータスが遷移し、カウンタが全0にリセットされ、実行状態が pending になり(凍結が解ける)、0 で終了する | |
| pending のタスク(「何もしない」ステータス滞留中)がある | 定義済みステータスへ set-status する | 受理されて遷移し、pending のまま 0 で終了する(abort を挟む必要はない) | |
| failed のタスクがある | 定義済みステータスへ set-status する | 受理されて遷移し、カウンタ全0・pending になる | |
| completed のタスクがある | 定義済みステータスへ set-status する | 受理されて遷移し、次ステータスへの自動遷移は行われなくなる(手動遷移が上書きする) | |
| 遷移先がエージェント実行のステータス | set-status する | 受理される(次のtickの動作は遷移先の定義に従う) | |
| 遷移先が「何もしない」(wait)ステータス | set-status する | 受理され、動作種別によらず一律にカウンタリセット・pending になる | |
| 遷移先がクリーンアップステータス | set-status する | 受理され、一律にカウンタリセット・pending になる(終端処理は次のtick) | |
| set-status が成功する | 結果を確認する | 遷移元(`from`)と遷移先(`to`)のステータス名が表示される | |

## 異常系

いずれの拒否・エラーでもタスクファイルには書き込まない。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| config.yaml が存在しない・パース不能・読めないのいずれか | set-status する | 非0で終了する(状態は変更しない。pages ※1) | |
| 別の操作が排他ロックを保持している | set-status する | 「別の操作が実行中」として非0で終了する | |
| ロック機構自体が異常(`LockError::Failed`) | set-status する | 実行環境エラーとして非0で終了する | |
| 指定IDのタスクが現役にもアーカイブにも存在しない | set-status する | タスク不在として非0で終了する | |
| 指定IDのタスクがアーカイブ済み | set-status する | アーカイブ済みは操作不可として非0で終了する | |
| 指定IDのタスクファイルがパース不能(`Corrupt`) | set-status する | 非0で終了し、破損ファイルへの書き込みは行わない | |
| スナップショットのみ読めないタスク(`SnapshotUnreadable`)がある | set-status する | 拒否して非0で終了する(遷移先の検証にスナップショットが必要。pages ※7) | |
| タスクが launching | set-status する | 拒否され「先に abort せよ」と案内して非0で終了する(`Active`) | |
| タスクが running | set-status する | 拒否され「先に abort せよ」と案内して非0で終了する(`Active`) | |
| 遷移先がスナップショット定義に存在しないステータス名 | set-status する | 定義済みステータスの一覧を添えて非0で終了する(`UnknownStatus`) | |
| タスクIDとして不正な文字列を指定する | set-status する | 入力境界の検証エラーとして非0で終了する | |
| ステータス名として不正な文字列を指定する | set-status する | 入力境界の検証エラーとして非0で終了する | |

## 境界値

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| タスクIDに空文字列を指定する | set-status する | 検証エラー(`Empty`)として非0で終了する | |
| タスクIDに65文字の文字列を指定する | set-status する | 検証エラー(`TooLong`)として非0で終了する | |
| タスクIDに `[a-z0-9-]` 以外の文字を含む・先頭が `-` の文字列を指定する | set-status する | 検証エラー(`InvalidChar` / `InvalidLeadingChar`)として非0で終了する | |
| ステータス名に空文字列を指定する | set-status する | 検証エラー(`Empty`)として非0で終了する | |
| ステータス名の前後に空白がある | set-status する | 検証エラー(`SurroundingWhitespace`)として非0で終了する | |

## エッジケース

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| `state/tasks/`・`state/archive/` ディレクトリが存在しない | set-status する | タスク不在として非0で終了する(pages 縮退表) | |
| 登録後に元YAMLへ追加されたステータス名を指定する | set-status する | スナップショットが検証の基準のため `UnknownStatus` として拒否される(定義更新は既存タスクに適用されない) | |
| 現在と同じステータス名を指定する | set-status する | 遷移経路の制約はないため受理され、カウンタリセット・pending になる | |
| stopped のタスクを set-status で動かした | 続けて同じタスクを retry する | 既に stopped ではないため retry は拒否される | |
| 到達不能ステータス(遷移経路のないクリーンアップ等)を遷移先に指定する | set-status する | スナップショットに定義済みであれば受理される | |
| kill 対象の残る可能性のあるタスク(abort 済みで孤児プロセス残存疑い) | set-status する | プロセス操作・worktree操作は一切行われず、タスクステータスの遷移のみが行われる | |
