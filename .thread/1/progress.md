## spec へ追従を提起した点

いずれも Issue #1 にコメントとして投稿済み。

- **エラー位置の粒度**（ADR-050）: spec/testcases/task/register-task.md の異常系は「config.yaml がパース不能(構文エラー・未知キー)→ エラー位置を表示」と書くが、ADR-021 の読み込み方（`Value` 化してから手書き走査）では行・列が取れるのは構文解析までで、スキーマ違反には行・列が残らない。実装は構文エラーに行・列を、スキーマ違反にファイルパスと論理位置（キーのパス）を示す。spec 側の語を「構文エラーは行・列、スキーマ違反はキーのパス」へ言い換える提案。
- **表示名を決められないファイル名の例示**（ADR-051）: spec は「拡張子を除くと空になるファイル名等」と例示するが、Rust の `Path::file_stem` は `.yaml` を語幹として返すため「拡張子を除くと空」は作れない。受け入れテストは語幹が空白のみになるファイル名（` .yaml`）で再現している。spec の例示に「語幹が空白のみ」を含める提案。
- **制約を持たない `InputText` の生成規約**: spec/domains/definition.md の名前系 newtype の表は「いずれも `parse(s: String) -> Result<Self, NameError>` でのみ生成する」と締めるが、`InputText` は同じ表の「制約なし」の行であり、`parse` にすると `Err` になる経路のない `Result` が残る。実装は `InputText::new(s: String) -> Self`（理由はコードに why として記載）。spec 側の「いずれも」を「制約のある型は」へ限定し、制約のない型は総関数で生成すると言い換える提案。
- **スナップショットフィールドの破損の作り方**（ADR-025）: ステップ12で投稿済み。

## 環境によってスキップされるケース

いずれも spec / plan.md が明示するスキップ運用に従う。現在の開発環境（macOS・非 root・一時ディレクトリはリポジトリ外）では **TC-port-clock-005 の1件を除き全件が実行された**。

| ケース | スキップ条件 |
|---|---|
| TC-task-register-task-016（config.yaml が読めない） | `chmod` が効かない環境（root 実行・非 POSIX） |
| TC-task-register-task-021（ワークフロー定義が読めない） | 同上 |
| TC-task-register-task-036（git リポジトリでないパス） | 一時ディレクトリ自体が git リポジトリ配下にある |
| TC-task-register-task-017（ロック競合） | `examples/lock_holder` を起動できない |
| TC-port-clock-005（時刻の巻き戻し） | ステップ13から継続。システム時計を過去に設定できないため常にスキップ |

TC-port-clock-005 はこの環境で常にスキップされるため、チェックリスト行にチェックを付けない。理由は Issue #1 のコメントに残した。
