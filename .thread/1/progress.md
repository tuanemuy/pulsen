# 進捗メモ — Issue #1

## spec へ追従を提起した点

いずれも Issue #1 にコメントとして投稿済み。

- **エラー位置の粒度**（ADR-050）: spec/testcases/task/register-task.md の異常系は「config.yaml がパース不能(構文エラー・未知キー)→ エラー位置を表示」と書くが、ADR-021 の読み込み方（`Value` 化してから手書き走査）では行・列が取れるのは構文解析までで、スキーマ違反には行・列が残らない。実装は構文エラーに行・列を、スキーマ違反に論理位置（キーのパス）を示す。対象ファイルの絶対パスが添うのは config.yaml のスキーマ違反だけで、ワークフロー定義のスキーマ違反には添わない（ADR-054 が範囲を限定した）。spec 側の語を「構文エラーは行・列、スキーマ違反はキーのパス」へ言い換える提案。
- **ワークフロー定義のスキーマ違反で対象ファイルを案内できないこと**（ADR-050 / ADR-054）: `WorkflowLoadError::Parse` は解決先パスを持たないため、`--workflow` を名前で指定したときに `<home>/workflows/<name>.yaml` のどこが壊れているかを案内できない。ポート表を `Parse { error, resolved_from }` へ改める提案。ポート表は spec が確定させており AC-7 の1:1一致の対象なので、本スライスでは実装を変えない。
- **表示名を決められないファイル名の例示**（ADR-051）: spec は「拡張子を除くと空になるファイル名等」と例示するが、Rust の `Path::file_stem` は `.yaml` を語幹として返すため「拡張子を除くと空」は作れない。受け入れテストは語幹が空白のみになるファイル名（` .yaml`）で再現している。spec の例示に「語幹が空白のみ」を含める提案。
- **制約を持たない `InputText` の生成規約**: spec/domains/definition.md の名前系 newtype の表は「いずれも `parse(s: String) -> Result<Self, NameError>` でのみ生成する」と締めるが、`InputText` は同じ表の「制約なし」の行であり、`parse` にすると `Err` になる経路のない `Result` が残る。実装は `InputText::new(s: String) -> Self`（理由はコードに why として記載）。spec 側の「いずれも」を「制約のある型は」へ限定し、制約のない型は総関数で生成すると言い換える提案。
- **エージェント単位の登録時検証エラーの重複**: `UnknownAgent` / `InvalidAgentDefinition` は spec/domains/definition.md の `RegistrationError` 5種のうち `status` を持たない2種、すなわちエージェント単位の誤りである。複数ステータスが同じ未定義エージェントを参照すると値まで同一のエラーが件数分返るため、実装は同じ値をすでに積んでいれば push しない。spec 側に「この2種はエージェント単位で1件にまとめる」を明記する提案。
- **スナップショットフィールドの破損の作り方**（ADR-025）: ステップ12で投稿済み。

## 環境によってスキップされるケース

いずれも spec / plan.md が明示するスキップ運用に従う。現在の開発環境（macOS・非 root・一時ディレクトリはリポジトリ外）では **TC-port-clock-005 の1件を除き全件が実行された**。

| ケース | スキップ条件 |
|---|---|
| TC-task-register-task-016（config.yaml が読めない） | `chmod` が効かない環境（root 実行・非 POSIX） |
| TC-task-register-task-021（ワークフロー定義が読めない） | 同上 |
| TC-task-register-task-036（git リポジトリでないパス） | 一時ディレクトリ自体が git リポジトリ配下にある |
| TC-task-register-task-017（ロック競合） | `examples/lock_holder` を起動できない |
| TC-port-exclusive-lock-002 / 003 / 004 / 005 | 同上（単一テストターゲットを指定した実行では example がビルドされない） |
| TC-port-clock-005（時刻の巻き戻し） | ステップ13から継続。システム時計を過去に設定できないため常にスキップ |

スキップは適合スイート・受け入れテストとも `SkipBudget` で許容ケース名を宣言し、集合外のスキップは失敗になる。上表の CLI 4件はこの環境（macOS・非 root・TMPDIR はリポジトリ外）では実走するため、許容集合は空である。

TC-port-clock-005 はこの環境で常にスキップされるため、チェックリスト行にチェックを付けない。理由は Issue #1 のコメントに残した。

## 記帳の順序と残作業

- **チェックリストの記帳はレビュー修正がすべて入った後に行う**: 走らなかったケースが `SKIP` として出力に現れる状態でないと「実装を確認できた」と数えられないため。この順序で 346行のうち 345行にチェックを付け、`TC-port-clock-005` の1件は付けずに理由を残した（確認した実行環境は Issue コメントに明記）。
- **MSRV 1.89 でのビルドが未検証**: `Cargo.toml` の `rust-version = "1.89"` は ADR-022（`File::try_lock` の安定化）に由来し、`std::env::home_dir()` の非推奨解除（1.87.0）より後なので宣言としては整合している。ただし devShell の rustc は 1.97.1 の1つだけで、CI もスコープ外（plan.md「含まれないもの」）のため、1.89 で実際にビルド・`clippy -D warnings` が通ることは一度も確認していない。CI を入れるスライスで MSRV ジョブを足して確定させる。
