2. **W-030 — probe 成立後のタイムアウトを失敗に倒す理由を、同じ ADR の 70行と同じ前提の上に立たせる**
   - 対象は「決定」の `probe が成立したあとのタイムアウトは失敗にする` の直後、`温まったあとの期限超過は環境の遅さではなく異常として読める` の一文。
   - 「起きえない」に寄せた断定をやめ、「probe が通った以上、この期限超過は環境の能力の宣言としては読めない。probe が測るのは1プロセスの単発の起動で、本番の負荷そのものは測定条件に入っていない（後述のトレードオフ）ため、繰り返すなら閾値の見直しとして扱う（ADR-071 の停止規則の内側）」の趣旨に直す。
   - 判断そのもの（失敗に倒す）は変えない。`spawn_holder` のパニック文言（`この環境で繰り返し起きるなら SIGNAL_DEADLINE を見直す`）と同じ語気に揃うことを確認する。

3. **W-031 — `SignalTimedOut` の腕にフィクスチャの退行も入ることを書く**
   - 「決定」の `合図が期限内に返らない(SignalTimedOut) → 能力側` の項か「影響」のトレードオフに1文足す: 「この腕には、保持プロセスが合図を返さなくなった退行も入る。probe は本番と同じ手順を踏むため両者を区別できず、`SKIP` 一覧に5件が並んだときは環境の遅さと同じだけフィクスチャの退行も疑う」。
   - **実装では塞がない。** probe が本番と同じ手順を踏む以上この2つは原理的に区別できず、機械的な歯止め（CI 側）は plan.md がスコープ外としている。区別が付かない事実を正本が正直に述べる形にするのが手当てである（実測: `lock_holder` に `sleep` を差し込むと未変更の `SIGNAL_DEADLINE` のまま4件が `SKIP` になり緑で終わる）。

4. **W-025 — probe の判定基準の射程を、読み取りが結果を返さずに終わった場合まで広げる**
   - 「決定」の `probe の判定基準は「合図が期限内に返ったか」だけに限る` の段落、`返ってきた合図を読み取れたかも、判定には入れない` に、読み取りが結果を返さずに終わった場合（読み取りスレッドが `send` に到達せず消えた場合）も含むことを1語〜1句で足す。
   - いまの綴りは「合図が返ってきた」ことを前提にしているため、`RecvTimeoutError::Disconnected` 経由でこの腕に入る経路を読み手が辿れない。

5. **W-037 — 期限の無い待ちについての断定を条件つきにする**
   - `期限の無い待ちは、正常に保持できたと分かっている相手にだけ許す` とその直後の probe についての段落は、無条件の性質として書かれている。実装がこれを満たすのは `kill` が確実に効く場合だけで、`kill_and_wait` に入るのは無期限の `wait()` である。
   - 「`kill` が届く限りにおいて」の条件を付し、届かない場合が残ることと、その手当てが Issue #15 の射程であることを1文で述べる。**ここで実装は変えない**（単位G）。
