## 検証したこと

観点ごとの確認結果を、指摘に至らなかったものも含めて残す。

- **OS 依存の隔離と `cfg` の分布（AC-1）**: `crates/*/src/` のターゲット述語つき `cfg`（`unix` / `windows` / `target_os` / `target_family`）は `pulsen-domain` に 0 件。`crates/pulsen/src/` 側は `util/atomic.rs` / `adapter/process.rs` / `adapter/task_repository.rs`（`#[cfg(all(test, unix))]`）の3ファイルのみで、計画どおり。`cli/wire.rs` は `IdentitySource::platform_default()` を呼ぶだけで `cfg` を持たない。テストターゲット側（`tests/cli_tick_missing_cwd.rs` の `#![cfg(unix)]` 等）は `src/` 外で対象外。
- **`unsafe` / 新規依存**: `unsafe` の追加なし。`process_group(0)` / `creation_flags` / `/proc` の読み取り / `ps` の起動だけで構成されており、`Cargo.toml` の依存は増えていない。
- **起動時刻・PGID の三値**: `identity::observe` はプラットフォームごとに1関数へ閉じ、戻り値は `Ok(Some)` / `Ok(None)`（対象不在）/ `Err(Io)`（機構失敗）。畳み込みは `own_identity` 側の1行にあり、共有関数には持ち込まれていない。POSIX は「非0 かつ stdout 空 → 不在」「それ以外の非0 → 機構失敗」、Linux は「procfs ルート不在 → 機構失敗」「`<root>/<pid>/stat` の `NotFound` → 不在」と、ADR-067 の写像表どおりに分かれている。ユニットテスト（不在・壊した取得元）も両方の分岐を踏む。
- **`ps` のロケール・TZ 注入**: `LC_ALL=C` / `TZ=UTC` を注入し `LANG` / `LC_TIME` を落とす。実バイナリで確認した記録は `"ident": "Thu Aug 13 03:34:40 2026"`（UTC・C ロケール）で、同時刻の対話シェルの `ps` 出力 `木 8/12 12:34:51 2026` と表現が独立していることを実測した。取得元は `/bin/ps` の絶対パスに固定。
- **`/proc` のパース**: 「最後の `)` より後ろ」を基準に `pgrp`（index 2）・`starttime`（index 19）を取るので、comm に空白や `)` を含むプロセスでも位置がずれない。boot id との合成で boot を跨いだ一致も消えている。
- **デタッチ起動 / FD の非継承**: stdin/stdout/stderr を `Stdio::null()`、`Child` を待たずに落とし、POSIX は `process_group(0)`、Windows は `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS`。セッションを分けない制約は doc に残っている。ロックFDは `OpenOptions`（std は O_CLOEXEC 付与）で開かれ、`cli_tick.rs` が「滞留中のラッパーがいる状態で次の tick が競合せず走る」ことで挙動として観測している。
- **`create` の冪等性の境界**: 達成済みと認めるのは「鍵が一致する登録が `ws.branch` を指し、実体があり、`prunable` でない」場合だけ。別ブランチの登録・worktree でない実体・base 不在はいずれも `Failed` で内容に触れない。復旧2分岐（`prunable` は `add -f`、登録なし・ブランチのみは `-f` なしの `add`）が両方とも適合ケースで実行される。正規化は `physical_key` を git の出力側にも対称に適用しており、フィクスチャの置き場もシンボリックリンク経由で組まれているので分岐が空振りしない。
- **アトミック置換・排他の共通化**: `FsRunStore` の write 系はすべて `util::atomic::write_atomic` 経由で、置き場の作成も `util::fsdir::ensure_dir` に集約。独自実装の再発明はない。
- **read 系の3分類**: 不在（ディレクトリごと不在を含む `NotFound`）→ `Ok(None)`、JSON 不正・値制約の破れ → `Corrupt { path, .. }`、その他 → `Io`。`marker_exists` は `exists()` ではなく `try_exists()` で、機構失敗を「無い」に丸めていない。
- **git のシェル非経由**: `Command` に引数を配列で渡し、`INHERITED_GIT_ENV` を落とす既存の規則を `create` も共有している。
- **エラーの握り潰し**: 握り潰しは `sync_dir`（既存・書き込み自体は成功済み）、`run_agent` の `Err(_) → 126`（契約）、`RunWrapper` の `write_exit`（契約）、`physical_key` の `canonicalize` 失敗（呼び出し側で `Failed` に写る）に限られ、いずれも理由が doc にある。
- **ポートの1:1（AC-6）**: `RunStore` 9・`ProcessController` 3・`WorktreeManager` に `create` 1 で spec の表と一致。`attempt_exists` / `list_runs` / `delete_attempt` / `remove_task_dir_if_empty` / `starttime_of` / `kill` / `try_kill_remnants` / `remove` の宣言もスタブも無い。
- **実効的なテスト（AC-7 / AC-8 / AC-9 / AC-16）**: `cargo fmt --check`・`cargo clippy --all-targets -- -D warnings`・`cargo test` を実行して全緑（0 failed / 0 ignored）。RunStore 22（21行 + 追加1）・WorktreeManager 17（16行 + 追加1）・ProcessController 16（13 + 3）が、この環境ではスキップ0で走っている。権限系の許容集合は `permission_restrictions_effective` から実行時に決まり、`agent_probe` / `spawn_probe` の不在は許容集合に入っていない。
- **argv の往復（実測）**: 実バイナリに対して `pulsen wrapper --run-dir ... --workspace ... -- <agent_probe> echo-args one -- two "" -x` を実行し、`--`・空文字列・`-x` がリテラルのまま `stdout.log` に現れることを確認した（`trailing_var_arg` + `allow_hyphen_values` が spawn 側の argv を落とさない）。
- **doc と実装の食い違い**: `HOOKS.md` の件数（9ポート169行 / A 38・B 113・C 18）と権限依存12行・区分C残6行の内訳はいずれも整合。ADR-067 の写像表・Linux のフィールド位置・既定の取得元も実装と一致。`progress.md` の既知の制限（Windows の `KillIdent` と取得元、単一テストターゲット指定でのプローブ不在、F4 の観測手段、TC-port-worktree-manager-015 の間欠失敗）はいずれもコードの記述と符合しており、隠された乖離は見つからなかった。W-001 が唯一の食い違い。
