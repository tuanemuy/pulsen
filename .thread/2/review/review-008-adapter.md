### Warnings

- **[W-001]** `adapter/process.rs` の冒頭が「OS 依存の分岐はこのファイルだけに置く(CLAUDE.md 技術方針)」と書いているが、事実に反する。/ `crates/pulsen/src/adapter/process.rs:3`。/ 同じターゲット述語つき `cfg` は `crates/pulsen/src/util/atomic.rs`(`sync_dir` の `cfg(unix)` / `cfg(not(unix))`)にもあり、plan.md AC-1 自身が3ファイルを許容範囲として数えている。`.thread/2/adr.md` の ADR-067 も「`#[cfg(unix)]` / `#[cfg(windows)]` の出現箇所が `adapter/process.rs` に増える(既存は `util/atomic.rs` のみ)」と書いており、モジュールドキュメントだけが「このファイルだけ」を主張している。読み手が「他に cfg があるなら隔離が破れている」と誤読する。/ 主語をこのファイルの責務に限る(例:「プロセス操作の OS 依存分岐はこのファイルに閉じる」)。CLAUDE.md の引用はアダプター層への隔離という原則を指しているので、引用自体はそのままでよい。

- **[W-002]** `prunable` 追加ケースのフィクスチャが、アダプターが「出力されないことがある」と明言している git の注記を前提条件にしている。/ `crates/pulsen/tests/conformance_worktree.rs:274-289`(`workspace_with_prunable_registration` の `registration.prunable.then_some(())?`)と `crates/pulsen/src/adapter/worktree.rs:214-221`。/ アダプターは「`prunable` の注記は git のバージョンで出力されないことがあり、注記だけを見ると実体の消えた登録が『達成済み』に倒れる」として `path.try_exists()` で実体を直接観測する設計にしている。ところがフィクスチャ側は注記が出ることを前提の成立条件にしており、注記を出さない git では `None` を返してスキップになる。このケースはスキップ許容集合(`SYMLINKED_ROOT_CASES`)にシンボリックリンクを張れない環境としてしか載っていないため、結果は**スキップではなくケースの失敗**になる。アダプターが守ろうとしている環境で、適合スイートだけが落ちる。最低 git バージョンはどこにも宣言されていない。/ 前提の確認をアダプターが実際に鍵にしている事実に揃える — 「登録が在る」かつ「`ws.path` の実体が無い」で判定すれば、注記の有無に依らず同じ状態を主張できる(登録も実体もフィクスチャ自身が作って消しているので観測可能)。注記そのものを前提にしたいなら、最低 git バージョンを宣言したうえでスキップ許容集合に載せる。
