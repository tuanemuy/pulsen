### Warnings

- **[W-001]** `tick` が自身の動作に不要なリソースの検証で落ちる / 場所: `crates/pulsen/src/cli/wire.rs:163-192`（`compose`）、呼び出しは `crates/pulsen/src/cli/tick.rs:25` / 理由: `compose()` は `env::current_dir()`（`FsWorkflowStore` の `base_dir` = `--workflow` の相対パス解決にしか使わない）と `DefaultTaskIdGenerator::new`（`getrandom` によるID発行の初期化）を無条件に行う。どちらも `tick` の動作には要らないリソースで、失敗すると `WireError::CurrentDirUnavailable` / `WireError::IdGenerator` として `tick` が非0で終わる。pages「縮退状態の共通規則1」（各コマンドは自身の動作に必要なリソースだけを検証する）と、まさにその規則を根拠に `current_exe()` を `compose()` から `wire::process_controller()` へ切り出した adr.md ADR-068 の判断に対して非対称になっている（`current_exe` は切り出し、`current_dir` と乱数は据え置き）。AC-12 が「tick は任意の作業ディレクトリから起動しても同じ結果になる」を掲げている以上、cwd への依存が結線に残っているのは読み手を惑わせる。失敗しても状態は変えず非0で終わるだけなので Blocker ではない / 提案: `process_controller()` と同型に `workflows`（`base_dir` を要する）と `ids` の構築を `compose()` から切り出して `add` の経路でだけ呼ぶ。切り出さないなら、ADR-068 に「乱数と cwd は `compose` に残す」判断とその理由を1行足して非対称を意図として残す。

### 確認した内容（要点）

- 依存方向: ドメインは `[dependencies]` 空のまま（Cargo.toml / Cargo.lock に差分なし = 新規依存ゼロ）。ターゲット述語つき `cfg`（`unix` / `windows` / `target_os` / `target_family`）は `crates/pulsen-domain/` に0件、`crates/pulsen/src/` は `adapter/process.rs` / `adapter/task_repository.rs` / `util/atomic.rs` の3ファイルのみ（AC-1 の期待どおり）。`cargo build --examples` / `cargo clippy --all-targets -- -D warnings` / `cargo fmt --check` / `cargo test --workspace` はいずれも通る。
- レイヤーの責務: 文言の組み立ては `cli::render`（`TickIssue` / `TransitionError` / `InconsistentRunFiles` はすべて分類だけを持つ）、レイアウト知識は `RunDirPath`（6つの導出関数と `state_root` の逆写像）、I/O は `adapter/`。帳簿に永続化される失敗要因だけがドメインの `describe` + ユースケースの文脈という2段構成（ADR-082）で、`cli/render.rs` に重複した文言は残っていない。
- 合成ルート: `current_exe()` の読み取りは `wire::process_controller()` の1箇所、ラッパーは `compose_wrapper(run_dir)` がホームも config も読まずに `RunDirPath::state_root()` から `FsRunStore` を組む（ADR-068 / ADR-070）。`Runtime` のアクセサはすべて呼び出し元がある。
- 未実装メソッド・スタブ: ポートの宣言は `RunStore` 9 / `ProcessController` 3 / `WorktreeManager::create` の1つだけで、`attempt_exists` / `list_runs` / `delete_attempt` / `remove_task_dir_if_empty` / `starttime_of` / `kill` / `try_kill_remnants` / `remove` はいずれも不在（AC-6）。`read_exit` は呼び出しが適合スイートだけだが、往復を契約として閉じる why がポートの doc にある。`todo!` / `unimplemented!` は0件。スコープ外（#3 / #6）の遷移・サービス・ポートの実装も紛れていない。
- 分岐の網羅: `branch_of` が実行状態と動作種別の網羅 `match` を1箇所で持ち、未配線の4アーム（`Cleanup` / `Observe` / `Advance` / `Notify`）は引き取り先のスライスを why コメントとして残し、ダミー処理も報告も置いていない（ADR-065 / ADR-083）。`tick_scan.rs` に「配線していない分岐のタスクにはエージェントを起動せず書き込みもしない」の主張がある。
- `tick` の終了コード: ロック競合 = 0（`TickOutcome::Skipped`、標準出力）、`LockError::Failed` と `list_active` の Io = 非0（標準エラー、状態不変）、サマリー = 0。`errors` が非空でも 0（pages 規則3）。実バイナリで確認済み。
- `wrapper`: `#[command(hide = true)]` でヘルプ一覧に出ず `pulsen wrapper --help` には到達できる。`--` 以降のエージェントコマンドは `trailing_var_arg` + `allow_hyphen_values` で受け、`-` 始まり・空文字列・シェルのメタ文字に加え、**トークンとしての `--` も往復する**ことを実バイナリで確認した（`echo-args alpha -- beta --gamma` が `alpha / -- / beta / --gamma` として渡る）。引数不正はすべて run ディレクトリに何も書かずに非0。結果は run ディレクトリのファイルにだけ現れ、標準出力には何も書かない。
- 出力: 実バイナリで `起動` → `起動確認` → `処理対象のタスクはありませんでした。` と、展開失敗の `失敗を記録(1件)` → 上限超過での `凍結` を確認した。書き込みを行った経路が必ずサマリーのいずれかを埋める不変（ADR-084 / ADR-086）は、`launch` / `ensure_workspace` / `confirm_spawn` の全経路で成立している（`save` 失敗時も `SaveFailed` が載る）。見出しの3分割（失敗を記録 / 起動の結果が未確定 / スキップ）は `issue_outcome` の網羅 `match` で決まる（ADR-090）。標準出力と標準エラーの使い分けは成功=stdout・失敗=stderr で一貫。
- ADR 参照: コード・テスト中の参照は `ADR-009`〜`ADR-090`。`ADR-064` 以下はすべて `.adr/` に実在し、`ADR-065`〜`ADR-090` は `.thread/2/adr.md` に連番で実在する（欠番・重複・dangling なし。`.adr/` の最大は 064 で衝突もない）。`.adr/027` の変更は「対応表の正本を `HOOKS.md` 一本にする」宣言で、`HOOKS.md` の集計（9ポート169行 = A38 + B113 + C18、各節の行数合計も169）と整合する。
