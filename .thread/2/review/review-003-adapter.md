### 確認した契約（記録）

- `cfg` の分布: `crates/pulsen-domain/` は0件。`crates/pulsen/src/` は `util/atomic.rs` / `adapter/process.rs` と、W-001 の `adapter/task_repository.rs`（テスト限定・main から存在）。`crates/pulsen-conformance/src/lib.rs` の1件は権限 probe（testing.md が明示的に扱いを書いている）。新規依存なし（`Cargo.toml` は無変更）、`unsafe_code = "forbid"` 維持、`cargo test` / `cargo clippy --all-targets -- -D warnings` / `cargo fmt --check` はいずれもグリーン（スキップ0件）。
- 同定情報の取得: `identity::observe` の1関数に閉じ、戻り値は三値。ADR-067 の写像表と実装が行単位で一致する — POSIX 非 Linux は「非0終了 かつ stdout 空 → `Ok(None)`」「それ以外の非0・exit 0 で空・PGID が読めない → `Err(Io)`」、Linux は「ルート不在 → `Err(Io)` / `<root>/<pid>/stat` が `NotFound` → `Ok(None)`」、Windows は「`$ErrorActionPreference = 'Stop'` + `catch` で非0終了 → `Err(Io)` / 完走かつ空 → `Ok(None)`」。プラットフォーム間で写像の形が違うのは各環境の実測（不在の現れ方）に対応しており、不在を機構失敗に畳む経路は無い。`own_identity` だけが `Ok(None)` を `Err(Io)` に畳み、畳む1行は共有関数の外にある。
- `ps` の環境固定: `LC_ALL=C` / `TZ=UTC` の注入と `LANG` / `LC_TIME` の除去を `identity_command` に閉じ、`Command::get_envs()` に対するユニットテストで主張している。取得元は既定 `/bin/ps` の絶対パス。
- `/proc/<pid>/stat` のパース: `rsplit_once(')')` で comm を切り落としてから空白分割し、`PGRP_INDEX = 2` / `STARTTIME_INDEX = 19`（全体の5番目・22番目）を取る。comm に空白・`)` を含む名前で位置がずれない。
- デタッチ起動: POSIX は `process_group(0)`、Windows は `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS`、両者とも stdio は `Stdio::null()` で `Child` を待たない。`setsid` 相当でないことは why コメントに残っている。実証は適合 TC-002（`examples/spawn_probe` が spawn 直後に終了し、その後にラッパーが完走）と、`cli_tick.rs` の「kill 同定子が `-<pid>` になる」= ラッパー自身がプロセスグループの長である、の2点。
- FD の継承: ロックは `OpenOptions` 由来の `File`（Rust は Unix で `O_CLOEXEC`、Windows で非継承ハンドル）で、`spawn_wrapper` は追加の FD を渡さない。`cli_tick.rs:167` の「滞留するエージェントを起動したままでも次の tick は競合しない」が空虚に成立しないよう `exit` の不在で生存を確かめてから読んでいる。
- アトミック置換・排他: `FsRunStore` の write 系3種とマーカーはすべて `util::atomic::write_atomic` 経由。ロックは `FileExclusiveLock` のみ。個別実装は無い。
- read 系の3分類: 不在（ディレクトリごと不在を含む）→ `Ok(None)`、JSON 構文と値制約の破れ → `Corrupt { path, message }`、その他の io エラー → `Io`。往復・並行観測・書き込み失敗後の非破壊は適合 21件 + 追加1件で押さえられている。
- `GitCliWorktreeManager::create`: 同定の鍵は `physical_key`（親のみ canonicalize + `file_name`）で、`ws.path` と `worktree list --porcelain` の各パスの**両側**に対称に適用している。達成済みの条件は「鍵一致 かつ 登録が `refs/heads/<ws.branch>` かつ 実体が在る かつ `prunable` でない」。実体の有無を `prunable` の注記ではなく `try_exists()` で直接見るため、注記を出さない git でも判定が倒れない。別ブランチの登録・通常ディレクトリ・base 不在はいずれも `Failed` で、自動修復も `-f` も行わない。ブランチのみ残存は `-f` なしの `worktree add` で先端を変えない。適合ハーネスは worktree_root をシンボリックリンク経由に組んで正規化の分岐を必ず通す。
- シェル非経由: `git` / `ps` / `powershell` / エージェントいずれも `Command` の直接起動で、引数はトークンのまま渡る。`BranchName::parse` が先頭ハイフンを弾き、`WorktreePath` は絶対パスなので、git へのオプション注入の経路は無い。
- エラーの扱い: 本番経路の `expect` は `run_agent` の「`CommandLine` は1トークン以上」1箇所（不変条件）だけ。握り潰しは `write_atomic` の `sync_dir`（why 付き・main から存在）と、ラッパーの `write_exit` 失敗（次 tick が分類する旨のコメント付き）に限られる。
- AC-6: `port.rs` に `attempt_exists` / `list_runs` / `delete_attempt` / `remove_task_dir_if_empty` / `starttime_of` / `kill` / `try_kill_remnants` / `remove` の宣言もスタブも無い。RunStore 9・ProcessController 3・WorktreeManager に `create` 1つ増、で spec のポート表と一致する。
- 残す必要のない記述: アダプター・examples・util のコメントに修正経緯・弁明・TODO の類は無い。
