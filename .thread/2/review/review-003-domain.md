### 確認したこと(指摘に至らなかった点)

- AC-2〜AC-6 の充足: `ExitCode` / `PidFileContent` と `RunDirPath` の6導出(+ `state_root` の逆写像)、`LaunchingClassifier` の `classify` / `classify_recheck` と境界(30秒非超過・31秒超過・巻き戻り0)、`Task` の問い合わせ5種と `WorkspacePlanner::derive`、遷移6種と `TransitionError` 5種、ポートのメソッド集合(RunStore 9 / ProcessController 3 / WorktreeManager +`create`)。いずれも spec と一致し、未実装メソッドの宣言・スタブはない。
- スコープ外の混入なし: `RunningClassifier` / `JudgementService` / `IdentityCheck` / `GcPolicy` / `NotificationService` / `RemoveOutcome` / `KillError` / `CommandCompletion` と `complete_run` 以降の遷移は `crates/pulsen-domain/` に1つも現れない。
- ターゲット述語つき `cfg` は `crates/pulsen-domain/` に0件。ドメインは std のみに依存し、共有可変状態を持たない。
- 網羅 `match`: 新規のドメインコード・ユースケースにワイルドカード(`_ =>`)はない。既存の3箇所(`definition/duration.rs` / `definition/assembler.rs` / `task/time.rs`)は本 PR の変更外。
- パニックは不変条件の破れに限る: `current_status_def`(不変条件1)、`WorkspacePlanner::derive`(TaskId の文字集合)、`AttemptNumber::next` / カウンタの飽和(到達不能領域)。いずれも why が添えられている。
- 表示の知識の分離: `TransitionError` / `InconsistentRunFiles` は分類だけを持ち(ADR-088)、`cli/render.rs` から `agent_def_error` / `template_error` の重複文言が消え、永続化される説明だけが `describe()` としてドメインに1箇所ある(ADR-082)。spec との差分(`expected: &'static str` / `InvariantViolated`・`CommandLine::rehydrate`・`RunDirPath::state_root`・write 系のディレクトリ作成)はすべて ADR と `progress.md` の「spec 追従の提起」に載っている。
- ドメインロジックの漏れなし: 猶予の判定・採番・カウンタ規則・凍結の判断はいずれもドメイン側にあり、`tick` 側は観測 → 判断 → 実行の配線に留まる(`Freeze` は ADR-089 の設計どおり遷移を呼んだ側が渡す)。
- コード・コメントに弁明や修正の経緯は残っていない(残っているのは why / why not のみ)。
