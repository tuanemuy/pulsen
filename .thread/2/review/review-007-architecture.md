### Warnings

- **[W-001]** Linux の同定情報取得が、ADR-067 の写像表にある「フィールドが形式外 → `Err(Io)`」を実装していない。
  場所: `crates/pulsen/src/adapter/process.rs` の `#[cfg(target_os = "linux")] mod identity::observe`(`fields.get(PGRP_INDEX)` / `fields.get(STARTTIME_INDEX)` の直後)。
  理由: 同ファイルの POSIX 非 Linux 側は `pgid.trim().parse::<u32>()` で最終トークンが PGID として読めることを確かめ、読めなければ `Err(Io)` に落としている(ADR-067 の macOS 行のとおり)。Linux 側は項目数(arity)しか見ておらず、`pgrp` / `ticks` が数値であることを確かめずに `format!("-{pgrp}")` / `format!("{boot_id}:{ticks}")` を組む。`ProcessStartTime::parse` / `KillIdent::parse` は非空しか見ないため、形式外の値が `Ok(Some(..))` として通る。`KillIdent` は pidファイル・タスクファイルに**永続化され** #3 の `kill` がそのまま使う値で、ADR-067 が「不正な同定情報で `Ok` を装わない」を写像表として書き下した趣旨(`TC-port-process-controller-005`)から外れる。取得元は ADR-068 で注入可能にしてあるため、「実在するが procfs ではないルート」は構成上作れる状態にある。
  なお実 `/proc` はこの2項目を常に数値で返すため、既定の取得元(`/proc`)で動く本番経路に実害は無い。優先度は低い。
  提案: `pgrp.parse::<u32>()` / `ticks.parse::<u64>()` を通してから組み立て、失敗を `Err(Io::Failed { .. })` に落とす(macOS 側と同じ形)。あるいは ADR-067 の Linux 行から「フィールドが形式外」を落として、arity だけを検査する旨に改める。どちらかで表と実装を一致させる。
